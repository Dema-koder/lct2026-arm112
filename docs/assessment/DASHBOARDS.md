# Дашборды и экраны: что видит преподаватель и что видит обучающийся

Четвёртый документ связки: [ASSESSMENT_AND_SCENARIOS.md](ASSESSMENT_AND_SCENARIOS.md) — как считается оценка, [ASSESSMENT_ML_ROADMAP.md](ASSESSMENT_ML_ROADMAP.md) — чем усилить, [METRICS.md](METRICS.md) — что измерять, здесь — **как это показать на экране**.

Задача документа: дать преподавателю возможность за минуту собрать недочёты обучающегося, увидеть слабые стороны группы и провести разбор занятия; обучающемуся — понять, что именно исправить.

Значок ⚙ — метрика требует доработок из [METRICS.md §1](METRICS.md#1-что-уже-можно-посчитать-а-что-требует-доработки) (таблица issues и поле в `draft.updated`). Без них экран строится, но часть блоков пустая.

---

## 1. Принципы

1. **Экран отвечает на вопрос, а не показывает данные.** «Кому подойти сейчас», «что разобрать на следующем занятии», «что мне исправить» — каждый блок существует ради конкретного решения.
2. **Один главный вопрос на экран.** Если блок не помогает ответить на вопрос экрана — он на другом экране.
3. **Ошибка важнее балла.** Балл 73 не говорит ничего; «трижды ошиблись в улице» говорит всё. Баллы — заголовок, ошибки — содержание.
4. **Сравнение вместо абсолюта.** Число само по себе не читается: рядом должен стоять норматив, медиана группы или прошлый результат обучающегося.
5. **Стиль АРМ-112.** Заказчик просил держаться реального интерфейса и минимизировать самодеятельность: те же таблицы `data-table`, плитки, `state-pill`. Диаграммы — inline SVG без библиотек, как уже сделано в `ReportCharts`.
6. **Приоритет преподавателя виден на экране.** Везде, где показан балл ИИ, рядом место для балла преподавателя и отметка, кто оценил.
7. **Пустое состояние честное.** «Данных мало — нужно ещё 2 занятия» вместо графика по одной точке.

## 3. Экраны преподавателя

| Блок | Метрики | Источник |
|---|---|---|
| Идёт сейчас | прогресс занятия, число участников в риске | `LessonMonitor` |
| Требует действия | неопубликованные зачёты, неподтверждённые эталоны, неоценённые сессии | `lesson`, `scenario`, `assessment` |

### 3.2 Монитор занятия (доработка существующего)

**Вопрос:** кому подойти сейчас?

Сейчас таблица показывает состояние, статус, карточки, время, итог. Что добавить:

| Колонка / блок | Метрика | Зачем |
|---|---|---|
| **Светофор риска** | просрочка ИЛИ пауза > 60 с ⚙ ИЛИ 2+ пропущенных вызова | Строка подсвечивается — сейчас подсвечивается только просрочка |
| Пропущено вызовов | `missedCalls` / `lost` | Сейчас видно только в итоговой оценке, а важно в моменте |
| Пауза | сколько секунд нет активности ⚙ | Отличает «думает» от «отошёл» |
| **Темп группы** над таблицей | медианное время на карточку vs норматив | Понять, что интенсивность взята не та |
| **Полоса прогресса занятия** | суммарно карточек закрыто / всего | Один взгляд вместо чтения 30 строк |

Сортировка по умолчанию — риск сверху, а не по АРМ.

| Блок | Метрика | Решение, которое принимает преподаватель |
|---|---|---|
| Шапка | медиана, разброс, доля уложившихся в норматив, число CRITICAL | Провалилась группа или два человека |
| Распределение итогов | гистограмма с отметкой «сколько ниже порога» | Кого собирать на дополнительное занятие |
| Слабые критерии | средний балл и **потеря в баллах** (`(100−балл)×вес/100`) | Какую тему разбирать — сортировка по потере, не по баллу |
| Типовые ошибки ⚙ | частота кода issue, severity | Готовый план разбора; ⛔ — критические |
| Ошибки по сценариям ⚙ | доля ошибок в разрезе сценария | Отделяет плохой сценарий от несвоенной темы |
| Матрица | тепловая карта баллов по критериям | Персональные рекомендации одним взглядом |

Ключевой приём — **сортировка по потере в баллах, а не по баллу**. Время 61 при весе 15 стоит группе 5.9 балла, адрес 72 при весе 40 — 11.2 балла: разбирать нужно адрес, хотя балл по нему выше.

Кнопка «разобрать на занятии» собирает выбранные ошибки в текст протокола и предлагает создать тренировку из сценариев, где эти ошибки встречались чаще всего.

| Блок | Метрика | Почему именно так |
|---|---|---|
| Динамика | итог по номеру сессии, зачёты отмечены отдельно | Падение после третьего занятия — сигнал, невидимый в одной оценке |
| Профиль по критериям | радар «он vs медиана группы» | Слабая сторона читается как форма, а не как таблица |
| Устойчивые недочёты ⚙ | в скольких занятиях подряд встречается код issue | **Главный блок экрана**: отличает случайную ошибку от закрепившейся привычки |
| Время внутри карточки ⚙ | время до адреса, до типа, смены типа, паузы — против медианы группы | Показывает *причину* медленной работы, а не факт |
| Покрытие типов | сколько карточек по категориям | Пробелы в подготовке: «ни одного газового вызова» |
| Вывод | автосборка из трёх блоков выше | Готовый черновик характеристики; преподаватель правит текстом |

Маркеры устойчивости недочёта: ⛔ не уходит (встречается в последних 3 занятиях), ↓ реже (частота падает), ✓ исправил (нет в последних 2).

### 3.5 Разбор сессии (доработка существующего)

**Вопрос:** что именно делал человек и справедлива ли оценка ИИ?

К существующей форме выставления баллов по критериям добавить:

| Блок | Содержание |
|---|---|
| **Сравнение с эталоном** | Две колонки по каждой карточке: что ввёл / что ожидалось, расхождения подсвечены. Для адреса — по полям (улица, дом, корпус) |
| **Таймлайн сессии** | Горизонтальная полоса: приход вызова, принятие, ввод полей ⚙, сохранение, просрочки. Видно, где встал |
| **Issues с привязкой** | Замечание кликом раскрывает карточку и подсвечивает поле |
| **Расхождение с ИИ** | Когда преподаватель ставит балл, рядом — «ИИ: 40, вы: 70». Копится для калибровки ([роадмап 2.7](ASSESSMENT_ML_ROADMAP.md)) |
| **Кнопка «согласен с ИИ»** | Явное подтверждение вместо «отсутствия правки» — это разметка для обучения, см. [METRICS.md §1](METRICS.md) |

### 3.6 Качество библиотеки сценариев (вкладка «Сценарии»)

**Вопрос:** какие сценарии чинить и чего не хватает?

| Блок | Метрика | Решение |
|---|---|---|
| Сводка по источникам | сколько TICKET / GENERATED / TRAINEE_MADE, доля подтверждённых | Сколько работы по подтверждению |
| Покрытие классификатора | карта категорий с числом сценариев | Сейчас перекос: OTHER 32, FIRE 25, MEDICAL 25, GAS 2, UTILITY 1 |
| Эмпирическая сложность vs заявленная | точечная диаграмма `difficulty` против среднего балла | Сценарий, помеченный «10», который решают все — вес неверный |
| Дискриминативность | корреляция балла за сценарий с итогом сессии | Сценарий, где все одинаковы, ничего не измеряет |
| Проблемные сценарии | доля ошибок > 80 % при подтверждённом эталоне | Либо эталон неверен, либо тема не пройдена |
| Неиспользуемые | ни разу не в занятии | Библиотека растёт, работает её часть |

## 4. Экраны обучающегося

Правило видимости прежнее: для зачёта — только после публикации (`requireVisible`), до этого «на проверке у преподавателя».

### 4.1 Мои результаты (доработка существующего)

К таблице занятий и рейтингу добавить в карточке оценки:

| Блок | Метрика | Формулировка на экране |
|---|---|---|
| **Вклад критериев в потерю** | `(100−балл)×вес/100` | «Адрес стоил вам 24 балла из 40» — сильнее, чем «72 %» |
| **Топ-3 ошибки** ⚙ | частые коды issue, критические первыми | Три пункта вместо списка из двадцати |

| Место в группе | ранг (есть) + перцентиль по времени | «по скорости медленнее 70 % группы» |
| Кто оценил | ИИ или преподаватель (есть) | Если правил преподаватель — показать его комментарий рядом |

### 4.3 Мой прогресс (новый)

**Вопрос:** я расту и над чем работать?

| Блок | Метрика | Формулировка |
|---|---|---|
| Кривая итогов | балл по номеру занятия | «+12 баллов за 6 занятий» |
| Профиль по критериям | радар «я vs медиана группы» | Тот же виджет, что у преподавателя — единый язык на разборе |
| Что улучшилось ⚙ | коды issue, исчезнувшие за последние 3 занятия | «Перестали пропускать службы» — признание прогресса |
| Над чем работать ⚙ | коды issue, встречающиеся стабильно | «Опечатки в улицах — 5 занятий подряд» |
| Норматив по занятиям | доля карточек в норматив, по занятиям | Видно, растёт ли скорость |
| Покрытие типов | какие категории отработаны | «Не было газовых вызовов» — можно попросить у преподавателя |

Сознательно **не показываем** обучающемуся: чужие баллы поимённо, полный рейтинг группы (только своё место), расхождение ИИ и преподавателя, эмпирическую сложность сценариев.

## 6. Виджеты

Всё — inline SVG без библиотек, как уже сделано в `ReportCharts` ([Lessons.tsx](../../frontend/app/components/teacher/Lessons.tsx)). Набор намеренно маленький: шесть виджетов закрывают все экраны.

| Виджет | Где | Особенность |
|---|---|---|
| **Полоса потери** | Обзор, Разбор занятия | Показывает потерю в баллах с учётом веса, не процент |
| **Гистограмма распределения** | Обзор | С отсечкой «сколько ниже порога» |
| **Радар по критериям** | Профиль, Мой прогресс | Всегда две линии: он и медиана группы |
| **Тепловая матрица** | Обзор | Три уровня, не градиент: читается без легенды |

| **Список недочётов** | везде | Строка = частота + формулировка + severity + ссылка на карточку |

Требования: понятно без цвета (дублировать формой и подписью), подписи по-русски, `aria-label` у каждого SVG, работает при 20 участниках в группе и при 2.

## 7. Чего на экранах быть не должно

| Антипаттерн | Почему | Как вместо |
|---|---|---|
| Балл без контекста | «73» не решение | Рядом норматив, медиана или прошлый результат |
| Список из 20 замечаний | Не читают | Топ-3 + «показать все» |
| Проценты вместо баллов потери | Скрывает вес критерия | «−11.2 балла из 40» |
| График по одной точке | Ложная динамика | «Данных мало: нужно ещё 2 занятия» |
| Ранг в группе меньше 8 человек | Шум выдаётся за оценку | Скрыть перцентиль, оставить абсолют |
| Поимённое сравнение для обучающегося | Демотивация, не входит в задачу | Только своё место и обезличенная медиана |
| Оценка ИИ как окончательная | Противоречит «приоритет всегда за преподавателем» | Всегда видно, кто оценил, и место для правки |
| Эталон в интерфейсе обучающегося до завершения | Задание решается копированием | Только в `hints` для TRAINING, после — в разборе |

## 8. Порядок внедрения

1. **Обзор занятия** (3.3) — максимальная польза на существующих данных; типовые ошибки подключатся после ⚙.
2. **Разбор занятия для обучающегося** (4.2) — шаблоны с подстановкой `expected`/`actual` из issues, без модели.
3. **Таблица issues** ⚙ ([METRICS.md §8](METRICS.md)) — оживляет блоки «типовые ошибки» и «устойчивые недочёты».
4. **Профиль обучающегося** (3.4) — ради него и нужна таблица issues; главный экран для характеристики.
5. **Дашборд** (3.1) — собирается из готовых к этому моменту агрегатов.
6. **Поле в `draft.updated`** ⚙ → блоки «время внутри карточки» в 3.4 и 4.2.
7. **Доработка монитора** (3.2) и **разбора сессии** (3.5) — светофор, таймлайн, «согласен с ИИ».
8. **Мой прогресс** (4.3) — когда у обучающихся накопится 3+ занятия.
9. **Качество библиотеки** (3.6) — вместе с п. 2.6 и 2.8 роадмапа.
