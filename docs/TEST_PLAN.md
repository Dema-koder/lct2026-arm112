# План тестирования: что и как проверять перед защитой

Руководство по проверке текущего `main` (`2fbff80`): три роли + усиление безопасности из [history/2026-09-20-integration-hardening.md](../history/2026-09-20-integration-hardening.md) + CI/CD с выкладкой на production.

Как читать:

- [TESTING_ROLES.md](TESTING_ROLES.md) — подробные пошаговые сценарии по каждой роли (экраны, кнопки, ожидания). Этот документ **не дублирует** их, а ссылается на них как на регрессию.
- Здесь — **что изменилось после того документа**, какие новые проверки обязательны, в каком порядке, на каких стендах, и что уже покрыто автотестами.
- Каждая проверка имеет идентификатор (`SEC-1`, `BKP-3`…), чтобы отмечать результат в чек-листе в конце.

## 1. Что изменилось и что из этого следует для тестов

| Изменение (коммит `1a42ccc`, `d5c697a`) | Риск, который закрывается | Что проверяем |
|---|---|---|
| **Немедленный отзыв JWT** (`V6__auth_version.sql`, валидатор в `SecurityConfig`): токен становится недействительным после блокировки, разблокировки, смены роли/профиля/пароля и после восстановления БД | Заблокированный или пониженный в правах пользователь продолжал работать до истечения токена (8 ч) | `SEC-1…SEC-5` |
| Проверка роли и активности преподавателя при создании/изменении группы | Группу можно было повесить на обучающегося или заблокированного | `GRP-1…GRP-3` |
| К группе можно прикрепить только `TRAINEE`; группа должна существовать; нельзя снять роль `TEACHER`, пока за ним группы | Осиротевшие группы, обучающиеся-«преподаватели» | `GRP-4…GRP-6` |
| Перед стартом занятия повторно проверяются участники (существуют, `TRAINEE`, активны) | Занятие стартовало для заблокированного участника | `LSN-1`, `LSN-2` |
| Материал нельзя назначить чужой группе; запись транзакционна, файл удаляется при ошибке БД; скачивание потоковое | Утечка материалов между преподавателями, битые записи, OOM на больших файлах | `MAT-1…MAT-4` |
| CSV-отчёт экранирует формулы, переносы строк и разделители в ФИО | CSV-инъекция при открытии в Excel | `RPT-1` |
| **Резервные копии**: уникальные имена, файлы материалов внутри ZIP, проверка состава копии, защита от path traversal, staging при восстановлении, отзыв всех JWT | Две копии в одну секунду перезаписывали друг друга; после восстановления материалы были битыми ссылками; злонамеренный ZIP мог писать вне каталога | `BKP-1…BKP-7` |
| Длина названия материала 1–200 (контракт + сервер) | Пустое/огромное название | `MAT-5` |
| Обновлены frontend-зависимости, `npm audit` = 0, Node 22.13+/24+ | Уязвимости в сборке; несовместимый Node | `CI-3` |
| **CI/CD**: проверки на PR, сборка образов в GHCR и выкладка на `http://103.112.71.71` при push в `main`, откат при неуспешном health check; nginx-прокси | Ручная выкладка, необновлённый production | `CI-1…CI-4`, `PROD-1…PROD-5` |

## 2. Стенды и порядок

| Стенд | Где | Когда использовать |
|---|---|---|
| **Локальный** | `docker compose up --build` → `localhost:3000` / `:8080` / PostgreSQL `:55432` | Всё функциональное, разрушающие проверки (восстановление, блокировки) |
| **Production** | `http://103.112.71.71` (через nginx, единый порт 80), Swagger `http://103.112.71.71/swagger-ui.html` | Только smoke после выкладки (раздел 7); **не** восстанавливать копии и не блокировать сидовых пользователей |
| **Автотесты** | `mvn clean verify` (в Docker при отсутствии JDK 21), `cd frontend && npm run lint && npm test` | Перед каждым PR; выполняются и в CI |

Рекомендуемый порядок одного полного прогона (~1,5 часа):

1. Автотесты (10 мин) — раздел 8.
2. Регрессия ролей по [TESTING_ROLES.md](TESTING_ROLES.md), разделы 1–3 (40 мин).
3. Новые проверки безопасности и целостности — разделы 3–6 этого документа (30 мин).
4. Smoke на production после мержа — раздел 7 (10 мин).

Перед разрушающими проверками (`BKP-*`, `SEC-*` с блокировками) держите три окна браузера с тремя ролями и Swagger с токеном администратора — часть ожиданий проверяется только по HTTP-коду.

## 3. Безопасность: отзыв токена и права

Предусловия: локальный стенд, чистая база (`docker compose down -v && up --build`), окно A — `admin`, окно B — обучающийся `ivanov` (создать через администратора, АРМ 4, Демо-группа).

| ID | Шаг | Ожидание | Автотест |
|---|---|---|---|
| SEC-1 | В окне B войти `ivanov`, открыть рабочее место. В окне A заблокировать `ivanov`. В окне B нажать «Мои результаты» | Окно B выбрасывает на экран входа (401 на первом же запросе), а не продолжает работать до истечения токена | ✅ `RolesAndAdminIntegrationTest` |
| SEC-2 | В окне A разблокировать `ivanov`. В окне B снова войти | Вход успешен; старый токен, если сохранён (Swagger), — по-прежнему 401 | ✅ |
| SEC-3 | В окне A у `ivanov` «изменить» → роль «Преподаватель» → Сохранить (группа должна быть снята, см. GRP-4) | Окно B: выброс на вход. После входа — экран преподавателя, а не АРМ | ручная |
| SEC-4 | В окне A «пароль» у `ivanov` → новый | Окно B: выброс на вход; вход со старым паролем — ошибка, с новым — успех | ручная |
| SEC-5 | Обучающийся сам меняет пароль (`POST /auth/password` через Swagger, токен обучающегося) | 204; тот же токен на следующем запросе — 401; новый вход работает | ручная |
| SEC-6 | Токен обучающегося → `GET /admin/users`, `GET /teacher/lessons`; токен администратора → `GET /trainee/context` | 403 во всех трёх случаях | ✅ |
| SEC-7 | Любой запрос с `X-Contract-Version: 0.2` | 426 `CONTRACT_VERSION_UNSUPPORTED` | ✅ (косвенно) |
| SEC-8 | Второй преподаватель (`teacher2`) → `GET /teacher/lessons/{id чужого занятия}` и `/teacher/sessions/{чужая}` | 403; список `GET /teacher/lessons` пуст | ✅ `TeacherFlowIntegrationTest` |
| SEC-9 | Аудит: после SEC-1…SEC-4 открыть «Журнал» администратора | Есть записи `POST /api/v1/admin/users/{id}/block`, `/unblock`, `PUT /api/v1/admin/users/{id}`, `/reset-password`, `POST /api/v1/auth/password`; в данных `"password":"***"`, `"next":"***"` | ✅ частично |

Особое внимание: после **любой** административной правки пользователя тот должен войти заново — это ожидаемое поведение, а не дефект (см. history, «Требует внимания»).

## 9. Что не покрыто и известные ограничения

- **Нет автотеста** на SEC-3/SEC-4/SEC-5 (отзыв токена при смене роли и пароля), GRP-4 (запрет снятия роли при закреплённых группах), LSN-1 (старт с заблокированным участником), BKP-5/BKP-6 (битая копия, path traversal) — только ручные проверки из этого документа. Кандидаты на добавление в `RolesAndAdminIntegrationTest`.
- Rate limiting входа не реализован: перебор паролей ничем не ограничен, кроме bcrypt.
- Копии лежат в Docker volume на том же хосте — внешнее хранилище не настроено; при потере сервера копии теряются вместе с ним.
- Production работает по HTTP без домена; после привязки домена нужен сертификат и правка `ARM112_ALLOWED_ORIGINS`.
- Идемпотентность команд в памяти процесса: после перезапуска backend повтор запроса с тем же `Idempotency-Key` выполнится заново.
- Восстановление копии прерывает все активные занятия и выбрасывает всех пользователей — планировать вне занятий.
