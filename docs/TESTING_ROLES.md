# Как протестировать роли вручную

Пошаговая проверка трёх рабочих мест на живом стенде. Каждый раздел — что открыть, что нажать, что должно произойти. В конце — как проверить то же через API и что покрыто автотестами.

## Подготовка

```bash
docker compose up --build
```

- Интерфейс: `http://localhost:3000`
- Swagger: `http://localhost:8080/swagger-ui.html` (`contractVersion` = `0.3`)

Сидовые учётные записи создаются при первом старте на пустой базе:

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `admin` |
| Преподаватель | `teacher` | `teacher` |
| Обучающийся | `trainee` | `trainee` (АРМ 12, в «Демо-группе») |

Удобнее держать три окна браузера — по одному на роль — в разных профилях или в приватных окнах: токен лежит в `sessionStorage`, одна вкладка = один пользователь.

Полный сброс стенда: `docker compose down -v && docker compose up --build`.

## 1. Администратор (`admin`)

После входа — верхнее меню: **Пользователи · Группы · Настройки · Журнал · Система**.

### 1.1. Пользователи

| Шаг | Ожидание |
|---|---|
| В строке-форме сверху создать обучающегося: логин `ivanov`, пароль `ivanov1`, ФИО, роль «Обучающийся», номер АРМ `4`, группа «Демо-группа» → **Создать** | Строка появляется в таблице, тост «Учётная запись создана» |
| Создать второго обучающегося с АРМ `7` в той же группе | Появляется в таблице |
| Создать пользователя с уже занятым логином | Красный баннер «Логин уже занят» |
| Создать с паролем короче 4 символов | Кнопка «Создать» неактивна |
| Переключатель «Активен» у `ivanov` → выключить | Строка серая. Вход `ivanov` в другом окне — «Неверное имя пользователя или пароль» |
| Включить обратно | Вход снова работает |
| Переключатель у самого `admin` | Неактивен — себя заблокировать нельзя |
| «изменить» → сменить АРМ на `5` → Сохранить | В таблице АРМ 5. У обучающегося в шапке после перезахода — «АРМ 5» |
| «пароль» → новый пароль `newpass1` | Вход со старым паролем — ошибка, с новым — успех |

Что проверяет: заведение трёх ролей, привязка АРМ к учётной записи (решение №2), блокировка без удаления результатов.

### 1.2. Группы

| Шаг | Ожидание |
|---|---|
| Создать группу «Группа 2», преподаватель `teacher` | Появляется в таблице, состав пустой |
| В «Пользователи» → «изменить» у обучающегося → группа «Группа 2» | В «Группы» участник переехал в новую группу |
| Сменить преподавателя группы в выпадающем списке | Сохраняется сразу |

### 1.3. Настройки

| Шаг | Ожидание |
|---|---|
| «Хранение журнала аудита, дней» → ввести `30`, уйти из поля | Красный баннер «не может быть меньше 180 дней», поле возвращается к прежнему значению |
| «Телефония: гудки, мс» → `2000`, уйти из поля | Тост «Сохранено». У обучающегося исходящий звонок теперь заметно дольше висит в «Вызов» |
| «Норматив принятия карточки, с» → `10` | Следующая карточка в журнале ДДС становится просроченной через 10 секунд |
| «Уровень логирования» → `DEBUG` | Сохраняется; в «Система → Лог сервера» появляются DEBUG-строки |

Кнопки «Сохранить» нет намеренно — сохранение по уходу из поля (решение №11).

### 1.4. Журнал

| Шаг | Ожидание |
|---|---|
| Открыть вкладку | Последние записи сверху: `POST /api/v1/admin/users`, `PUT /api/v1/admin/settings` и т. д. с логином и ролью |
| Фильтр по роли «Обучающийся» | Только действия обучающихся (после того как кто-то из них поработает) |
| Фильтр по действию `users` | Только создание/правка пользователей |
| Раскрыть «Данные» у записи создания пользователя | В теле `"password":"***"` — пароль не сохранён |
| «Показать ещё» внизу | Подгружается следующая страница |

Что проверяет: аудит всех изменяющих действий всех ролей (решение №4).

### 1.5. Система

| Шаг | Ожидание |
|---|---|
| Открыть вкладку | Сервис UP, база UP, число WebSocket-подключений, активных сессий, версия `0.3.0` |
| **Сделать копию сейчас** | В списке появляется `arm112-ГГГГММДД-ЧЧММСС.zip` |
| Создать ещё одного пользователя, затем «восстановить» у сделанной копии → ввести `RESTORE` | Тост «База восстановлена». Созданный после копии пользователь исчез, остальные на месте |
| «восстановить» с любым другим словом | Кнопка неактивна |
| Лог сервера | Последние строки лога backend |

## 2. Преподаватель (`teacher`)

Меню: **Занятия · Сценарии · Материалы**. Преподаватель видит только свои группы, занятия и материалы (решение №8) — чтобы это проверить, заведите через администратора второго преподавателя и убедитесь, что его список занятий пуст.

### 2.1. Сценарии

| Шаг | Ожидание |
|---|---|
| Открыть вкладку | 96 билетов + сценарии, сформированные обучающимися (если уже есть). Фильтры по категории и источнику |
| Открыть `ticket-02-1` | Вводная «Задымление мусоропровода…», уточнённый адрес Берзарина 21 к. 1, тип «Задымление в жилом доме», службы по ЕКП |
| Изменить сложность на `8`, сохранить | Тост «Сценарий сохранён» |
| **Подтвердить эталон** | В списке «✓ подтверждён» |
| Открыть билет без типа (например `ticket-05-3`), выбрать тип плашкой, сохранить | Службы по ЕКП подставились автоматически |
| Категория «Пожары», «сгенерировать» 3 | Три сценария `gen-…` с источником «Сгенерированные», эталон не подтверждён |

### 2.2. Занятие: создание и старт

| Шаг | Ожидание |
|---|---|
| **Новое занятие** | Форма: название, группа, вид, режим, сценарии галочками, участники галочками с номерами АРМ |
| Вид «Проверка», режим «Заполнение карточки», сценарии `ticket-01-1` и `ticket-02-1`, участники — `trainee` и `ivanov` → **Создать** | Открывается занятие в состоянии «Не начато», в мониторе две строки с АРМ 12 и АРМ 4/5 |
| **Начать** | Состояние «Идёт». В окне обучающегося без перезагрузки появился экран оператора 112 с вводной |
| Кнопка «Создать» при пустом списке сценариев или участников | Неактивна |

### 2.3. Монитор

Пока обучающиеся работают (см. раздел 3):

| Шаг | Ожидание |
|---|---|
| Смотреть таблицу | Обновляется сама (WebSocket + опрос раз в 5 с): «Заполняет» → «Сохранена», счётчик карточек `1 / 2`, время работы тикает |
| Обучающийся держит карточку дольше 3 минут | Ячейка статуса красная, «просрочена отработка» |
| Режим ДДС: обучающийся не открыл карточку 30 секунд | «просрочено принятие» |

### 2.4. Завершение и отчёт

| Шаг | Ожидание |
|---|---|
| Дождаться, пока оба сохранят все вводные | Занятие само перешло в «Завершено» |
| Либо **Завершить занятие** досрочно | Незавершившие получают оценку по факту (нетронутые карточки — 0 за действия) |
| Раздел «Отчёт» | Строки с АРМ, оценкой по времени, числом синтаксических ошибок, уровнем (рейтинг), оценкой ИИ, итогом; две диаграммы; рейтинг занятия |
| «выгрузить CSV» | Файл `lesson-….csv`, открывается в Excel с русскими буквами (BOM, разделитель `;`) |

### 2.5. Оценка преподавателя

| Шаг | Ожидание |
|---|---|
| Клик по строке обучающегося | Разбор: вводная, введённый адрес, типы, службы, описание; блок «Оценка системы и итог» с замечаниями (например, «Опечатка в названии улицы») |
| Оценка `85`, комментарий, **Сохранить оценку** | Итог стал 85 с подписью «оценка преподавателя», оценка системы осталась рядом |
| Вернуться в отчёт | В столбце «Оценка преп.» 85, «Итог» 85 |

Что проверяет: решение №5 — оценка преподавателя рядом с ИИ и становится итоговой.

### 2.6. Зачёт и публикация

| Шаг | Ожидание |
|---|---|
| Создать занятие вида «Зачёт», режим «Действия с карточкой», источник «Сгенерированные», `ticket-01-1`, участник `trainee` → Начать | У обучающегося — журнал ДДС с карточкой |
| Обучающийся отработал и сдал (раздел 3.2) | В «Мои результаты» у него — «на проверке у преподавателя» |
| **Завершить занятие** → кнопка «Опубликовать результаты» | Неактивна, пока не оценены все участники (подсказка при наведении) |
| Поставить оценку → **Опубликовать результаты** | У обучающегося результат открылся без перезагрузки |

Что проверяет: решение №10 — три правила видимости по виду занятия.

### 2.7. Источник «сформированные обучающимися»

После того как кто-то сохранил карточку в режиме заполнения:

| Шаг | Ожидание |
|---|---|
| «Сценарии» → источник «Сформированные обучающимися» | Сценарии `trainee-…` с адресом, который ввёл обучающийся |
| Новое занятие, режим «Действия с карточкой», источник «Сформированные обучающимися» | В списке сценариев только они; после старта в журнале ДДС карточка с этим адресом |

### 2.8. Материалы

| Шаг | Ожидание |
|---|---|
| Выбрать PDF/DOCX, название, группу → **Загрузить** | Строка в таблице с размером и группами |
| У обучающегося «Мои результаты» → внизу «Методические материалы» | Файл скачивается по клику |
| «удалить» | Исчезает у преподавателя и у обучающегося |

## 3. Обучающийся (`trainee`)

После входа — либо активное занятие, либо «Занятие ещё не назначено». Меню: **Рабочее место · Мои результаты**. При старте занятия преподавателем экран меняется сам.

### 3.1. Режим заполнения карточки (экран оператора 112)

Из коробки для `trainee` уже идёт демо-тренировка по `ticket-01-1` и `ticket-02-1`.

| Шаг | Ожидание |
|---|---|
| Открыть рабочее место | Экран с оранжевой панелью «Службы:» внизу, таймер справа сверху считает вверх и показывает «отработать за 03:00», жёлтая плашка «Заявитель сообщает: Возгорание мусорного контейнера…» |
| ☎ рядом с АОН | Плашка вводной прячется/показывается |
| Кнопка «АОН» у «предоставленного» | Копирует номер заявителя |
| В «Улица» ввести `МЖД Кеевская 1 км. 2` (с опечаткой), дом — пусто, строение `2` | Через ~0,5 с поле желтеет, под адресом «💡 Улица не совпадает с уточнённым адресом заявителя» — это подсказка **тренировки** |
| Исправить на `МЖД Киевская 1 км. 2` | Подсказка исчезает |
| «Что случилось?» → ввести `мус` | Выпадает «Пожар: мусор»; клик — синяя плашка, ниже открывается опросная карта «Что горит / Что видит заявитель / Есть угроза…» |
| Ответить на вопросы плашками | Строка «Класс.: пожар: мусор;» |
| Панель служб | Синие плитки «по ЕКП»: Служба 101, 102, 103, 104, ЦЭМП, ЦОДД, ОАТИ… — подобрались сами |
| «+» на панели | Окно: автоподобранные синие и неактивные (удалить нельзя), остальные серые; клик по серой добавляет → плитка «вручную» |
| Описание — набрать текст | Счётчик `NN / 1999` |
| **сохранить** без типа происшествия | Красный баннер «Выберите тип происшествия» |
| **сохранить** с заполненными полями | Тост «Карточка … сохранена», сразу открывается вторая вводная (задымление мусоропровода, Ким Олег Юрьевич), в шапке «в очереди ещё 0» |
| Заполнить вторую и сохранить | Экран «Все вводные занятия отработаны» и (для тренировки/проверки) окно результата: адрес / тип / службы / время / грамотность, замечания, рекомендации |
| Ждать больше 3 минут перед сохранением | Таймер красный; в результате «Карточка заполнялась дольше норматива» |

Разница по видам занятия (проверить, создав три занятия у преподавателя):

| Вид | Подсказки по ходу | Результат после последнего сохранения |
|---|---|---|
| Тренировка | есть | сразу |
| Проверка | нет | сразу |
| Зачёт | нет | «на проверке у преподавателя», пока не опубликуют |

### 3.2. Режим действий с карточкой (экран ДДС)

Преподаватель должен запустить занятие режима «Действия с карточкой».

| Шаг | Ожидание |
|---|---|
| Журнал | Карточка со статусом «Добавлена», синий таймер обратного отсчёта 30 с справа |
| Не открывать 30 секунд | Ячейка «Статус службы» красная; при открытии подсказка (тренировка) «Норматив 30 секунд уже превышен» |
| Открыть карточку | В ленте «Получена службой», таймер в шапке «принять за…»; на панели внизу все оповещённые службы, плитка «Служба 101» — своя, остальные тусклые и не кликаются |
| Клик по своей плитке → карандаш ✎ | Меню «Принята / Не принята» |
| «Не принята» | Строка ввода комментария над панелью, ✓ неактивна при пустом комментарии |
| Ввести комментарий, ✓ | Статус «Не принята», в меню остаётся только «Принята» — единственный выход |
| «Принята» | Таймер «отработать за 03:00», меню: «Начало реагирования / Отказ от выполнения работ» |
| Попробовать пропустить шаг | В меню нет «Работы завершены» — только следующий по цепочке |
| «Исходящий звонок» → 1102 → Вызвать | Верхняя полоса: «Набор номера» → «Вызов» → «Соединение установлено» → «Информация принята» (~1,2 с при настройках по умолчанию) |
| «Работы завершены» без звонка (если звонка не было) | Красный баннер «Не выполнен обязательный исходящий звонок» |
| Прибытие → Проведение работ → Работы завершены с комментарием | Лента заполнена сверху вниз; в журнал приходит следующая карточка (если в занятии их больше одной), тост «Новая карточка в журнале» |
| Все карточки завершены | В шапке журнала кнопка **Завершить занятие**; до этого её нет |
| Завершить занятие | Окно результата (проверка/тренировка) или тост «результат появится после проверки» (зачёт) |

### 3.3. Мои результаты

| Шаг | Ожидание |
|---|---|
| Открыть | Таблица занятий: вид, режим, итог, кто оценил (система / преподаватель); чип «Рейтинг NN · место k из N» |
| Клик по строке с результатом | Разбор оценки; если преподаватель ставил свою — «оценка преподавателя» в круге, «Оценка системы» рядом, комментарий преподавателя |
| Строка зачёта до публикации | «на проверке у преподавателя», не кликается |
| Преподаватель опубликовал | Строка становится кликабельной без перезагрузки |
| Внизу «Методические материалы» | Файлы, назначенные группе |

### 3.4. Чего обучающийся не должен мочь

| Попытка | Ожидание |
|---|---|
| Открыть `http://localhost:8080/api/v1/teacher/lessons` с токеном обучающегося (Swagger) | `403 FORBIDDEN` |
| `GET /api/v1/assessments/{id}` с id чужой оценки | `403` |
| `GET /api/v1/cards?sessionId=<чужой>` | `403` |
| Открыть результат зачёта до публикации по прямому `GET /assessments/{id}` | `403 RESULTS_NOT_PUBLISHED` |

## 4. Проверка через API (Swagger или curl)

Вход и токен:

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' -H 'X-Contract-Version: 0.3' \
  -d '{"username":"teacher","password":"teacher"}' | python -c 'import sys,json;print(json.load(sys.stdin)["accessToken"])')
```

Дальше — `-H "Authorization: Bearer $TOKEN" -H 'X-Contract-Version: 0.3'`.

| Что | Запрос |
|---|---|
| Роль в токене | `GET /auth/me` → `"role": "TEACHER"` |
| Занятие с двумя участниками | `POST /teacher/lessons` `{"title":"…","kind":"CHECK","mode":"CARD_FILL","cardSource":"GENERATED","scenarioIds":["ticket-01-1"],"traineeIds":["<id1>","<id2>"]}` → `POST /teacher/lessons/{id}/start` |
| Монитор | `GET /teacher/lessons/{id}/monitor` — по строке на участника с его `workstationNumber` |
| Черновик обучающегося | `POST /card-drafts {"sessionId":…}` → `PATCH /card-drafts/{id}` → `POST /card-drafts/{id}/save` (заголовок `Idempotency-Key: <uuid>`) |
| Повтор с тем же `Idempotency-Key` | Тот же ответ, без второго сохранения |
| Оценка преподавателя | `PUT /teacher/sessions/{sessionId}/assessment {"total":88.5,"comment":"…"}` → в ответе `"source":"TEACHER"` |
| Публикация зачёта | `POST /teacher/lessons/{id}/publish` — `409 NOT_EXAM` для не-зачёта, `409 LESSON_NOT_COMPLETED` до завершения |
| Аудит | `GET /admin/audit?action=lessons&limit=10` (токен администратора) |
| Настройка ниже минимума | `PUT /admin/settings {"audit.retention_days":"30"}` → `422` |
| Копия и восстановление | `POST /admin/backups` → `POST /admin/backups/{fileName}/restore {"confirm":"RESTORE"}` → `204` |
| Неверная версия контракта | Любой запрос с `X-Contract-Version: 0.2` → `426` |

Realtime: `POST /auth/ws-ticket` → `ws://localhost:8080/ws/v1?ticket=…`. Обучающийся получает события своей сессии (`card.created`, `draft.saved`, `training.session_started`, `results.published`), преподаватель — события всех сессий своих занятий, администратор — ничего из учебных событий.

## 6. Известные ограничения при тестировании

- `DemoSeeder` на пустой базе запускает тренировку для `trainee`: первое занятие «уже идёт». Старт нового занятия у того же обучающегося принудительно закрывает предыдущее.
- Служба обучающегося — всегда `101`. Карточки, по ЕКП не оповещающие 101 (например, «задымление: квартира» в текущих данных), ожидают отказа «Не принята»; принять их — ошибка в оценке, а не системы.
- 20 из 96 билетов без автоматически определённого типа — их эталон по типу/службам не считается, пока преподаватель не проставит тип в редакторе сценария.
- Звук исходящего вызова не воспроизводится — только стадии в верхней полосе.
- Восстановление из копии прерывает все активные занятия.
