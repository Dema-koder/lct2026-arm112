# Скриншоты боевого интерфейса ПОВ-112

Извлечены из `materials/СКРИНШОТ ДДСГСИ.docx` (→ `dds-NN.png`, 20 шт.) и `materials/СКРИНШОТ КАРТОЧКИ 112ГСИ.docx` (→ `card-NN.png`, 9 шт.). Нумерация соответствует порядку изображений в исходных документах.

Это **референс, к которому заказчик просил привязаться**: «Интерфейс должен быть похожим и максимально близким к реальному, включая цветовые решения. Лучше привязаться к имеющемуся шаблону и меньше самодеятельности» ([q-and-a.md](../q-and-a.md), раздел 5). По запросу заказчик готов дать скриншот любого нужного экрана.

Снимки сделаны 17.09.2026 на стенде `10.0.99.36` под учётной записью `umc_operdds1` (АРМ 4, УМЦ — учебно-методический центр).

> СТАТУС ПРИНЯТО/НЕ ПРИНЯТО формируется путем выбора из двух статусов, остальные поля заполняются в ручную
> Далее при нажатии карандашика можно проставлять новые статусы (НАЧАЛО РЕАГИРОВАНИЯ / ОТКАЗ ОТ ВЫПОЛНЕНИЯ РАБОТ / РАБОТЫ ЗАВЕРШЕНЫ) и комментарии

> После выбора информации АВТОМАТИЧЕСКИ ПОДТЯГИВАЮТСЯ СЛУЖБЫ которые можно дополнительно подтягивать в ручную
> Далее для примера (КРАСНЫЙ ЦВЕТ ПОЛЯ ГОВОРИТ О ТОМ ЧТО ВРЕМЯ НАБОРА КАРТОЧКИ ПРЕВЫШЕНО)

## Палитра и типографика

Считано с кадров, значения приблизительные:

| Роль | Цвет |
|---|---|
| Фон рабочей области | светло-серый, ~`#EDEDED` |
| Блоки/карточки | белый |
| Шапка списка происшествий, плашки заголовков | тёмно-серый, ~`#4A4A4A` |
| **Акцент оператора-112: нижняя панель с кнопкой «сохранить»** (`card-*.png`) | оранжевый, ~`#E8622A` |
| Нижняя панель служб на АРМ **ДДС** (`dds-12.png`, `dds-16.png`) | серо-синий, ~`#5A6A72`; оранжевого на этом экране нет |
| Раскрытая (активная) плитка службы на АРМ ДДС | синий, в тон ленте истории |
| Служебные кнопки («просмотр», «дополнение»), выбранные признаки, история статусов | синий, ~`#2A6FB5` |
| Предупреждения: «нет контакта», «срыв звонка», превышение норматива | красный / светло-красный |
| Основной текст | почти чёрный; подписи полей — серый мелкий |

Шрифт — системный без засечек (Roboto/Arial-подобный). Плотная сетка, тонкие разделители, минимум скруглений и теней. Часы и таймер — крупные, светлые на тёмном.

> Ключевая мысль заказчика про интерфейс: «Цель системы — не плодить сущности, а как можно быстрее забивать данные и переходить к следующему звонку. Поэтому минимум времени на интерфейс, основные силы — в ядро».
