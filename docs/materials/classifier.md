## Зачем этот файл

Это **механизм, который в реальной системе превращает выбранные оператором признаки в список служб**. Из Q&A (раздел 4): «Справа у него теги-подсказки, по которым он заполняет опросную карту. Программа по этим тегам автоматически подтягивает внизу список служб, которые нужно вызвать».

ЕКП — единственный источник истины для этого. Он согласован со всеми службами, и именно поэтому инструкция запрещает оператору править список служб вручную в штатной ситуации.

Для тренажёра ЕКП даёт сразу три вещи:

1. **эталон** для проверки правильности классификации обучающегося;
2. **генератор сценариев** — 1283 готовых типа происшествий с реалистичной структурой;
3. **связь с задачей ДДС** — какие карточки вообще приходят в конкретную службу (именно по колонке этой службы).

## Структура таблицы

Две строки заголовка. Первая — группы колонок (названия служб), вторая — сами колонки.

Колонки 1-14 — описание происшествия:

| № | Колонка | Смысл |
|---|---|---|
| 1-4 | `Г`, `п1`, `п2`, `п3` | Служебные уровни иерархии |
| 5 | `Номер` | Код происшествия, 7 цифр: `1010101` = группа 01, подгруппа 01, признак 01, вариант 01 |
| 6 | `Группа происшествий` | Учёт в статистике Службы 112 (верхний уровень, 103 уникальных значения) |
| 7 | `112 - Признак.1 (тип происшествия)` | Первый уровень опросной карты (274 значения) |
| 8 | `112-Признак.2` | Второй уровень |
| 9 | `112-Признак.3` | Третий уровень |
| 10 | `Дополнительные признаки` | Не влияют на тип происшествия |
| 11 | **`Итоговый тип происшествия`** | Результат комбинации признаков — то, что видит ДДС |
| 12 | `ТИП происшествия ЕКП 35` | Укрупнённая классификация |
| 13 | `Сценарий реагирования` | Код сценария (`1_2`, `1_11`, `1_26`…) |
| 14 | `Главная служба` | Ведущая служба / формулировка для ЕКП |

Колонки 15-99 — **матрица оповещения**: по колонке на службу. Непустая ячейка означает «служба оповещается», а её значение — это тип происшествия **в классификаторе самой службы**.

Значения-маркеры в матрице:

| Значение | Смысл | Частота |
|---|---|---|
| `карточка-112` | Служба получает карточку без собственной типизации | ~13 300 |
| `нет реагирования` | Колонка заполнена, но служба не реагирует | 740 |
| Конкретный тип (`Пожар`, `Травма`, `ДТП с пожаром`, `АВТО`…) | Тип в классификаторе этой службы | остальное |

Пример строки (ДТП без пострадавших, номер `2010000`):

```
группа:        Дорожно-транспортные происшествия без пострадавших
признак 1:     ДТП
итоговый тип:  ДТП без пострадавших
ЕКП-35:        ДТП без пострадаших        ← опечатка в исходнике
сценарий:      Police
оповещаются:   Классификатор МВД, Мосгортранс, ЦОДД, Аппарат МЭРА,
               ГКУ НТУ, ФСО, ЦУКБ Министерство обороны, ГКУ Организатор перевозок
```

Пример с несколькими классификаторами (пожар при ДТП, сценарий `1_11`): МЧС получает «Пожар: Транспортное средство», МВД — «ДТП с пожаром», СМП — «АВТО», ЦЭМП — «нет реагирования», остальные 15 служб — «карточка-112».

## Как использовать в тренажёре

**Генерация сценария:** взять строку ЕКП → признаки дают опросную карту, итоговый тип даёт заголовок карточки, матрица даёт корректный список служб. Текст «со слов заявителя» можно генерировать по признакам, а эталоном считать саму строку.

**Проверка действий обучающегося-оператора-112:** сравнить выбранные им признаки с эталонной строкой; расхождение по итоговому типу — грубая ошибка, расхождение по третьему уровню — мелкая.

**Проверка действий обучающегося-ДДС:** карточки, приходящие в конкретную службу, — это строки, где колонка этой службы непуста. Отказ («Не принята») по карточке, где служба присутствует в ЕКП как реагирующая, — то самое «нарушение: отказ от реагирования на профильное происшествие» из [dds-workflow.md](dds-workflow.md).

**Ограничение для честности:** реальный поиск по признакам третьего уровня в ПОВ-112 не реализован (см. памятку ДДС). Копировать этот баг не обязательно.
