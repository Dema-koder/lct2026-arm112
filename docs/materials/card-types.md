# «Что случилось?» и опросные карты

Источник: `materials/КАРТОЧКА 112.docx` — список типов верхнего уровня текстом и 39 скриншотов опросной карты, переданы заказчиком 21.09.2026 (сообщение #685). Машиночитаемая версия — [`data/card-types.json`](data/card-types.json); сидами лежат `seed/card-types.json` (список) и `seed/survey-trees.json` (карты).

## Как это устроено в ПОВ-112

Ответ заказчика 21.09 (#683): «Коды сценария реагирования это технические номера разработчиков программы 112. **Под каждый сценарий реагирования для оператора 112 закладывается своя опросная карта.** Для диспетчеров сценария нет. Под сценарием реагирования подтягиваются определённые ДДС.»

То есть оператор 112 не выбирает «тип происшествия ЕКП» напрямую. Он выбирает позицию из списка «что случилось?» — это верхний уровень, их 49 — и дальше отвечает на вопросы опросной карты этой позиции. Тип по классификатору и состав служб получаются из ответов.

## Что достроено нами

Скриншоты есть только для «Происшествия 101», и только для веток «Улица» и «Транспорт». Остальное помечено флагом `synthetic: true` — на экране такие вопросы выводятся со звёздочкой и подсказкой «ветка достроена по смыслу». Достроены:

- ветки «Дом», «Здание / объект», «Опасный объект» карты 101;
- карты для 102, 103, 104, ДТП, аварий в городском хозяйстве и на транспорте, человека в опасности, ребёнка в опасности, взрыва, угрозы теракта, обрушения и угрозы обрушения, животных, смертельного исхода, скопления воды, природной стихии, иностранного языка;
- для остальных позиций списка карта пустая — только «Описание», как у справочных и служебных типов.

Пока эти карты не подтверждены заказчиком, оценка по ним не строже, чем по типу ЕКП: важен итоговый тип и состав служб.

## Вывод типа ЕКП из ответов

В `seed/survey-trees.json` у каждой карты есть `rules` — список правил «набор ответов → тип ЕКП» и `defaultType`. Первое подошедшее правило выигрывает. Примеры для 101:

| Ответы | Тип |
|---|---|
| Улица + Запах гари | `fire.smoke` |
| Улица + пламя + Трава/Парк/Лес/Торф/Дерево | `fire.grass` |
| Улица + пламя + остальное | `fire.garbage` |
| Транспорт + Сработала сигнализация | `fire.alarm` |
| Транспорт + пламя | `fire.vehicle` |
| Дом + Задымление или Запах гари | `fire.smoke` |
| Дом | `fire.apartment` |
| Здание / Опасный объект | `fire.building` |

Для позиций без соответствия в ЕКП («Благодарность службам», «Сбор», справки) заведены собственные типы `top.<id>` — они нужны, чтобы карточку можно было сохранить и оценить.

Обратная совместимость: старый эндпоинт `GET /references/survey-cards/{incidentTypeId}` продолжает отдавать плоскую карту по типу ЕКП (помечен `deprecated` в контракте 0.3.3).
