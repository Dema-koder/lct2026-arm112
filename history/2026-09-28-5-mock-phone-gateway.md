# 2026-09-28 — локальный mock-шлюз телефонии

**Ветка:** `feat/mock-phone-gateway`
**Коммит:** `—` (заполнить после коммита)
**Суть:** локальная среда теперь полностью воспроизводит звонок, callback и переход на резервный номер без подключения к реальной УПАТС.

## Что сделано

### Фронтенд

- В разделе администратора «Сервисы» добавлен локальный режим проверки звонков.
- Можно выбрать принятие без результата, ответ, отсутствие ответа, ошибку callback или недоступность шлюза и задать задержку.
- История попыток во время локальной проверки обновляется автоматически.

### Бэкенд

- Добавлен отдельный mock-контейнер телефонного шлюза без внешних зависимостей.
- Mock принимает звонки с серверным токеном и отправляет в backend тот же callback, который должен использовать реальный шлюз.
- Добавлено безопасное серверное управление тестовым сценарием; токен не передаётся в браузер.
- Обычный локальный Compose запускает mock с основным и резервным тестовыми номерами.
- Добавлены unit-тесты управления mock-шлюзом.

### Контракт

- OpenAPI обновлён с `0.3.10` до `0.3.11`.
- Добавлены `GET/PUT /admin/system/alerts/mock` и схемы настроек тестового сценария.

### Документация

- README, инструкция по выкладке и `.env.example` дополнены порядком локальной проверки.
- Зафиксировано, что mock отсутствует в production Compose.

## Почему так

Mock вынесен в отдельный контейнер, чтобы проверять настоящий сетевой обмен между шлюзом и backend, включая авторизацию callback. Production-файл его не содержит, поэтому тестовая телефония не может включиться на сервере после обычной выкладки.

## Проверено

- Полная backend-сборка со всеми тестами в Docker прошла успешно.
- Frontend lint, production-сборка и тесты прошли успешно.
- Оба Compose-файла проходят проверку конфигурации.
- В поднятом локальном стенде проверена цепочка `NOT_ANSWERED`: первая попытка получила callback, после неё автоматически создан звонок на второй номер, обе записи завершились статусом «не ответили».
- Проверена недоступность шлюза: обе попытки записываются как ошибочные, API тестового звонка возвращает ожидаемый HTTP 502.
- Все четыре локальных контейнера находятся в состоянии healthy.

## Не сделано

- Реальный звонок через УПАТС не выполнялся: для него нужны адрес, токен и номера внутреннего шлюза организации.
- Mock намеренно не добавлен в `compose.production.yaml`.

## Требует внимания

- `ARM112_ALERT_CALL_MOCK_CONTROL_URL` должен оставаться пустым в production; текущий production Compose вообще не передаёт эту переменную.
- После ручного подключения реального шлюза локальный блок выбора сценария станет недоступен, если его control URL и токен не совпадают с mock-контейнером; это ожидаемое поведение.
