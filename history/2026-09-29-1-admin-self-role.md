# 2026-09-29 — администратор не может сменить свою роль

**Ветка:** `fix/admin-self-role`
**Коммит:** `—` (заполнить после коммита)
**Суть:** администратор больше не может разжаловать сам себя и остаться без доступа к админке.

## Что сделано

### Фронтенд

- `AdminShell.tsx`, окно «Учётная запись»: выбор роли для своей записи заблокирован.
- Поля «Номер АРМ» и «Группа» показываются только для роли «Обучающийся», как в форме создания. При смене роли на другую они уходят на сервер как `null`.

### Бэкенд

- `UserService.update` принимает id того, кто вносит изменение. Если админ пытается сменить роль своей записи, запрос отклоняется с 422 `VALIDATION_ERROR` «Нельзя сменить роль своей учётной записи». Изменить своё ФИО по-прежнему можно.
- `AdminController.updateUser` передаёт в сервис `CurrentUser`.

### Контракт

- без изменений: 422 от `PUT /admin/users/{id}` бэкенд возвращал и раньше (валидация группы), в `openapi.yaml` он не описан.

### Документация

- без изменений

## Почему так

Воспроизведено на тестовом стенде, последовательность видна в `audit_event`:

1. Админ открыл свою запись. Поле группы было видно для любой роли, и он выбрал в нём группу.
2. Сервер ответил 422 «К учебной группе можно прикрепить только обучающегося».
3. Роль в форме переключили на «Обучающийся», и сервер это сохранил. Других админов в системе не было, поэтому вернуть роль можно было только через SQL.

Роль меняет только администратор. Поэтому запрета на смену своей роли достаточно, чтобы в системе всегда оставался хотя бы один активный админ: самоблокировку `setActive` запрещал и раньше. Отдельный подсчёт администраторов не нужен.

## Проверено

- `RolesAndAdminIntegrationTest.enforcesRolesAndWritesAudit`: смена своей роли даёт 422, роль остаётся `ADMIN`, правка своей записи без смены роли даёт 200.
- Полная сборка бэкенда с тестами (`mvn clean package` в Docker) и сборка фронтенда на тестовом стенде.

## Не сделано

- В `openapi.yaml` нет ответа 422 для `updateUser`. Не добавлял, чтобы не поднимать версию контракта ради документации уже существующего поведения.

## Требует внимания

- `UserRepository.update` при любой правке записи поднимает `auth_version`, поэтому админ, сохранивший своё ФИО, тут же выходит из системы. Поведение старое, я его не менял. Если это будет мешать, для правок без смены роли и группы версию можно не поднимать.
- Если в тестовой БД админ уже стал обучающимся, восстановить так: `update app_user set role='ADMIN', group_id=null, workstation_number=null, auth_version=auth_version+1 where login='admin'`. Рост `auth_version` отзывает выданные токены.
