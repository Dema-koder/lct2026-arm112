# 2026-09-19 — жизненный цикл карточки и приближение интерфейса к оригиналу

**Ветка:** `main`
**Коммит:** [`1316716`](https://github.com/Dema-koder/lct2026-arm112/commit/1316716)
**Суть:** карточка проходит полный цикл статусов реагирования как в реальной системе-112, интерфейс приведён к боевым скриншотам ПОВ-112, материалы задачи разобраны в читаемую документацию.

## Что сделано

### Бэкенд

- **Добавлены три статуса реагирования**: «Получена службой» (`RECEIVED_BY_SERVICE`), «Прибытие» (`ARRIVED`), «Проведение работ» (`WORK_IN_PROGRESS`). Было шесть состояний, стало девять — как в памятке ДДС.
- **«Получена службой» проставляется автоматически при открытии карточки** диспетчером (`GET /cards/{id}`), от имени системы, а не обучающегося.
- **Статусы проставляются строго последовательно**: `Принята → Начало реагирования → Прибытие → Проведение работ → Работы завершены`. Перепрыгнуть нельзя, попытка возвращает 409 `INVALID_STATE_TRANSITION`. Исключение — «Отказ от выполнения работ», он доступен на любом этапе после приёма.
- **Из «Не принята» разрешён возврат в «Принята»** — раньше отказ был необратимым тупиком с пустым `allowedActions`.
- Исходящий звонок разрешён из любого рабочего состояния, а не только из «Начало реагирования».
- Технические события ленты («Добавлена», «Получена службой») подписываются автором «Система».

### Фронтенд

- Статусы переименованы в женский род: **«Принята» / «Не принята»** (согласуются с «карточкой»).
- **Лента истории в прямом хронологическом порядке** (был обратный), с автором события и полной датой.
- **Кнопка «Завершить занятие» перенесена в шапку журнала** и видна, пока занятие активно. Раньше она появлялась только внутри карточки при статусе «Работы завершены» — то есть после отказа занятие нельзя было сдать вообще.
- **Плитки служб**: время последнего статуса вместо тикающих текущих часов, подпись из `service.code` («Служба 101») вместо угадывания по подстроке «Пожар», меню привязано к конкретной плитке.
- **Жест проставления статуса как в оригинале**: клик по плитке раскрывает её (синяя, шеврон), на раскрытой появляется карандаш, и только он открывает список статусов.
- **Форма ввода статуса переехала** из модалки по центру в строку над панелью служб: статус, поле комментария, кнопки ✓ и ✕.
- **Таймер карточки** — крупный блок справа вверху: время работы с карточкой вверх, под ним остаток до норматива, при просрочке красный.
- **Шапка поиска переделана**: «Поиск происшествий» — плейсхолдер внутри широкого поля на всю ширину с лупой справа, под ним «расширенный по параметрам» и «сбросить». Было — заголовок `<h1>` плюс маленькое поле на `position: absolute`, которое разъезжалось на узких экранах.
- **Сетка журнала стала адаптивной**: вынесена в `--journal-cols`, две ступени (≤1500px и ≤1250px), ужимаются только служебные колонки. На 1280px «Тип происшествия» получил 266px вместо 229 — заголовок демо-карточки перестал обрезаться. На обрезаемые ячейки добавлен `title`.
- **Строка «Описание:»** показывает реальный текст происшествия с автором и датой, как в оригинале, вместо дубля типа происшествия.
- Красная индикация просрочки перенесена с таймера на ячейку статуса в журнале.
- На экране входа вернулись контакты техподдержки `+7 (495) 197-89-81` и `hd-112@mos.ru`, ссылка на Swagger убрана в нижний угол.

## Почему так

**Последовательность статусов.** Памятка ДДС, раздел «Проставление статусов реагирования», дословно: «Выбрать статусы реагирования **можно только последовательно**». Перечисление пяти статусов в следующей фразе — это состав второго уровня списка в целом, а не набор доступных одновременно. Сначала было реализовано «вперёд с пропусками» — неверно, исправлено.

**Возврат из «Не принята».** Та же памятка, «Что делать если…»: «Ошибочно проставили статус "Не принята", т.е. реагирование будет осуществляться → Проставить статус "Принята"». Три из семи категорий нарушений в памятке построены вокруг этого сюжета, без него половина учебных сценариев непроигрываема.

**Оранжевый цвет панели служб отменён.** Сначала нижняя панель была покрашена в оранжевый — ошибка: оранжевая панель принадлежит экрану **оператора-112** (кадры `card-*.png`), где внизу кнопка «сохранить». Симулируем АРМ **ДДС**, там панель серо-синяя (`dds-12.png`), а отличается от нашей только цвет активной плитки — он синий. Откачено, документы поправлены.

**Второе поле в `CardListItem`.** Для строки «Описание:» по формату оригинала нужен автор карточки. Без `senderLabel` пришлось бы захардкодить «Оператор 112» — ровно та заглушка, которая помечена дефектом в аудите. Поле уже существует в полной карточке, это проброс, а не новая сущность.

**Захардкоженные поля оставлены намеренно.** `Пострадавшие: нет`, `[ВИС] Класс: —`, `АРМ 12`, округ-заглушка, пагинация — при текущей демо-карточке выводят логически верные значения и в оригинале выглядят так же. Список с обоснованием — в разделе «Сознательно не делаем» плана.

## Проверено

- **Сборка образа с тестами** — проходит. Интеграционный тест дополнен шагами «Прибытие» и «Проведение работ» **и проверкой, что преждевременный `COMPLETE` возвращает 409** — регрессия по правилу последовательности теперь ловится автоматически.
- **Полный сценарий через API** на живом бэкенде: открытие → «Не принята» с комментарием → исправление на «Принята» → Начало реагирования → Прибытие → Проведение работ → звонок 1102 → завершение звонка → Работы завершены. Лента событий совпадает с образцом из памятки.
- **Попытки перепрыгнуть статус** из «Принята» во все три последующих — все три отклонены с `INVALID_STATE_TRANSITION`.
- **`COMPLETE` без обязательного звонка** — отклонён с понятным сообщением.
- Фронтенд: `tsc --noEmit` и `eslint` без замечаний, production-сборка и `tests/rendered-html.test.mjs` проходят.
- Синхронность enum'ов Java и контракта сверена скриптом.

## Не сделано

- **Реальный состав служб.** В карточке одна служба, по ЕКП на происшествие оповещается в среднем 16.5. Данные готовы в `docs/materials/data/classifier.json`, нужна правка сида бэкенда.
- **Звук исходящего вызова.** `CallMedia` приходит с `null`, поле `CallTarget.voice` не используется, стадия `RINGING` не наступает — звонок проскакивает в `ACKNOWLEDGED` за 0.67 с.
- **Оценка грамотности.** `languageScore` возвращает 100 всегда, включая текст с намеренными ошибками и текст на английском.
- **Оценка обоснованности отказа.** Отказ от профильного происшествия без работы оценивается на 100 баллов из 100.
- **Многозадачность**, расширенный поиск, горячие клавиши, опросная карта, мобильная вёрстка.
- Технический долг фронтенда: переподключение WebSocket при каждом открытии карточки, опрос звонка раз в 500 мс с полной перезагрузкой карточки.

## Требует внимания

- **`additionalProperties: false` в контракте** означает, что любое следующее поле в ответе требует правки `openapi.yaml` в тот же заход. Автоматической сверки нет — сейчас enum'ы сверялись разовым скриптом. Стоит сделать тест.
- **Правки файлов скриптами на Windows ломают переносы строк.** Четыре файла были переписаны с CRLF, из-за чего дифф раздулся с 300 до 1823 строк. Возвращено к LF; при правках через python использовать `newline=""` и не допускать `\r\n`.
- **Правила в `.gitignore` без ведущего слэша совпадают на любом уровне.** Правило `materials/` тихо исключало `docs/materials/` со всей разобранной документацией.
- **Невалидный путь API отдаёт 500 вместо 404**, стектрейсы не логируются вообще — любая опечатка в пути выглядит как падение сервера.
- Билеты в `tickets.md` распознаны вручную по скану, возможны опечатки в именах и номерах.
