# 2026-09-28 — понятное администрирование

**Ветка:** `fix/admin-usability`
**Коммит:** `—`
**Суть:** администратор может удобно назначать обучающихся в группы и видит понятные подсказки для поиска, сервисов и телефонного шлюза.

## Что сделано

### Фронтенд

- У фильтра журнала появились видимая подпись, полная подсказка и адаптивная ширина.
- При создании группы можно сразу выбрать обучающихся; состав существующей группы можно изменить в отдельном окне.
- Поиск обучающихся работает по ФИО, логину и номеру АРМ, а в списке видна текущая группа.
- Каждая карточка служебного модуля объясняет его назначение, последствия остановки и случаи, когда нужен перезапуск.
- Для аварийного звонка показана пошаговая настройка без изменения исходного кода.

### Бэкенд

- Добавлена атомарная замена состава группы.
- Бэкенд проверяет, что все выбранные записи существуют и являются активными обучающимися.
- В API сервисов добавлены поля с понятными описаниями назначения и действий.

### Контракт

- OpenAPI обновлён с `0.3.8` до `0.3.9`.
- Добавлен `PUT /api/v1/admin/groups/{id}/members` и расширена модель `ManagedService`.

### Документация

- Добавлена эта запись в историю разработки.

## Почему так

Секретный токен телефонного шлюза остаётся на сервере: его нельзя безопасно читать или менять из браузера. Поэтому интерфейс показывает точное место настройки, но не передаёт секрет на фронт.

## Проверено

- `mvn -q -DskipTests compile`.
- `mvn -q -Dtest=RolesAndAdminIntegrationTest test`.
- `npm run build` и `npm test -- --test-reporter=spec`.
- OpenAPI успешно разобран YAML-парсером, `git diff --check` без ошибок.
- Docker-образы пересобраны, backend и frontend здоровы.
- Журнал, группы, окно состава, подсказки сервисов и настройка звонка проверены в живом браузере.

## Не сделано

- Настоящий тестовый звонок не выполнялся: на локальном стенде нет реквизитов внутреннего телефонного шлюза.

## Требует внимания

- Назначение обучающегося в другую группу автоматически убирает его из прежней.
- Перед production-включением звонков нужно согласовать с ИБ адрес шлюза, служебный токен и номер дежурного.
