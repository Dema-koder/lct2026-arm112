# 2026-09-20 — объединение ролей и усиление безопасности

**Ветка:** `integration/roles-hardening`  
**Коммит:** `—` (заполнить после коммита)  
**Суть:** функциональность трёх ролей объединена с PostgreSQL-версией проекта, а найденные при ревью проблемы доступа, бэкапов и зависимостей закрыты до слияния в `main`.

## Что сделано

### Фронтенд

- В интеграционную ветку включены интерфейсы администратора, преподавателя и обучающегося, оба режима занятий и контракт `0.3`.
- React, Vite, vinext, Wrangler и Cloudflare Vite plugin обновлены до версий без известных npm-аудиту уязвимостей.
- Диапазон Node.js ограничен поддерживаемыми LTS-версиями: Node 22 начиная с 22.13 либо Node 24+.
- Vite-конфигурация подготовлена к native loader: JSON импортируется с import attribute, локальный TypeScript-модуль — с расширением.

### Бэкенд

- Добавлена миграция `V6__auth_version.sql`. Старые JWT немедленно отзываются после блокировки, разблокировки, смены роли, профиля или пароля; после восстановления БД отзываются все ранее выпущенные JWT.
- Проверяются роль и активность преподавателя при создании и изменении группы.
- Нельзя прикрепить к группе пользователя не с ролью `TRAINEE`, указать несуществующую группу или снять роль `TEACHER`, пока за преподавателем закреплены группы.
- Перед стартом занятия повторно проверяются наличие, роль и активность всех участников.
- Преподаватель не может назначить материал чужой группе. Запись материала и связей с группами транзакционна, а файл удаляется при ошибке БД.
- Скачивание материалов переведено на потоковую отдачу файла вместо загрузки всего содержимого в heap.
- CSV-отчёт защищён от формул, переноса строк и разделителей в имени обучающегося.
- Имена резервных копий сделаны уникальными.

### Резервные копии

- ZIP теперь содержит не только прикладные таблицы, но и физические файлы методических материалов.
- Перед очисткой БД проверяется наличие всех обязательных разделов копии.
- Имена файлов внутри ZIP проверяются от path traversal.
- Материалы сначала распаковываются во временный каталог, затем заменяют текущие; пути в таблице `material` переписываются под текущее окружение.
- Старые копии без файлового раздела остаются совместимыми.

### Контракт и документация

- Для названия загружаемого материала зафиксирована длина от 1 до 200 символов.
- README и инструкция тестирования уточняют состав бэкапа и немедленный отзыв JWT.

## Почему так

Исходная feature-ветка была функционально готова, но позволяла использовать уже выданный JWT после блокировки, назначать материалы чужим группам и восстанавливать только метаданные материалов без самих файлов. Эти случаи приводили бы к обходу административных ограничений или к битым ссылкам после восстановления.

Обновление frontend-зависимостей выполнено до версий, на которых текущие lint, production-сборка и HTML-тесты продолжают проходить; `npm audit` после обновления сообщает о нуле известных уязвимостей.

## Проверено

- `mvn clean verify` — 9 backend-тестов, 0 ошибок.
- `npm run lint` — без замечаний.
- `npm test` — production-сборка и 2 frontend-теста проходят.
- `npm audit --audit-level=high` — 0 уязвимостей.
- Интеграционный тест дополнительно проверяет отзыв старого JWT, запрет преподавателя у группы, запрет раздачи материала чужой группе и восстановление физического файла из копии.
- `docker compose up` — PostgreSQL применяет миграции `V1–V6`, все контейнеры проходят health check.

## Не сделано

- `main` намеренно не изменён: результат отправлен отдельной третьей веткой для командного просмотра.
- Идемпотентность команд по-прежнему хранится в памяти, transactional outbox между snapshot и realtime-событием не добавлен.
- Rate limiting входа и внешнее хранилище резервных копий требуют отдельного инфраструктурного решения.

## Требует внимания

- После смены пароля, роли, активности или восстановления копии пользователю нужно войти заново — это ожидаемое поведение.
- Для рабочего стенда обязательно заменить сидовые пароли и `ARM112_JWT_SECRET` в `.env`.
- Локальные резервные копии лежат в Docker volume `backend_data`; для защиты от потери хоста их нужно дополнительно выгружать во внешнее хранилище.
