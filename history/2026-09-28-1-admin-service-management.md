# 2026-09-28 — управление сервисами из кабинета администратора

**Ветка:** `feat/admin-service-management`
**Суть:** администратор видит состояние всех компонентов и может безопасно останавливать, запускать и перезапускать учебные runtime-модули.

## Что сделано

### Фронтенд

- Добавлена отдельная вкладка «Сервисы» с карточками frontend, backend, PostgreSQL, движка симуляции, телефонии, доставки событий и фоновых заданий.
- Для управляемых модулей добавлены действия «Запустить», «Остановить» и «Перезапустить» с подтверждением и понятным описанием последствий.
- Показаны прикладные метрики: активные сессии и звонки, WebSocket-подключения, состояние очереди заданий, версии backend и PostgreSQL.

### Бэкенд

- Добавлены административные ручки списка сервисов и выполнения разрешённых действий.
- Состояние runtime-модулей хранится в PostgreSQL и восстанавливается после перезапуска.
- Остановка реально приостанавливает симуляцию, новые звонки, WebSocket-доставку или обработку фоновой очереди; после запуска работа продолжается.
- Backend, frontend и PostgreSQL доступны только для просмотра: управление их жизненным циклом оставлено Docker/CI, чтобы не выдавать приложению Docker socket.

### Контракт

- OpenAPI обновлён с `0.3.6` до `0.3.7`: добавлены `ManagedService`, `ServiceMetric`, `ServiceAction` и две административные ручки.

### Документация

- Эта запись фиксирует границу между безопасными runtime-действиями и инфраструктурным управлением.

## Почему так

ТЗ требует запуск, остановку и мониторинг сервисов администратором. Сам backend не может безопасно остановить и затем запустить себя, а доступ к Docker socket дал бы приложению права на весь сервер. Поэтому учебные модули управляются непосредственно из кабинета, а инфраструктурные компоненты показывают состояние и честную подсказку «управляется через Docker/CI».

## Проверено

- Полный `mvn test`, включая интеграционные и нагрузочные тесты.
- Интеграционный тест RBAC, переключения фоновых заданий и запрета остановки backend через API.
- Сборка frontend и его тесты.
- Сборка Docker-образов, миграция PostgreSQL до V18, healthcheck всех трёх контейнеров.
- Ручной просмотр вкладки «Сервисы» в браузере.

## Не сделано

- Запуск и остановка Docker-контейнеров из веб-интерфейса. Для этого нужен отдельный минимально привилегированный агент управления на сервере.

## Требует внимания

- Остановка доставки событий не удаляет их: накопленные события отправятся после повторного запуска.
- Остановка телефонии запрещает новые звонки; незавершённые звонки продолжаются после запуска модуля.
