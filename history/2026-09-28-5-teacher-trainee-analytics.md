# 2026-09-28 — аналитика преподавателя и обучающегося

**Ветка:** `feat/teacher-analytics-filters`
**Коммит:** `1c36095`
**Суть:** фильтры и дашборд аналитики преподавателя, согласование итога с ИИ, динамика оценок обучающегося за месяц.

## Что сделано

### Фронтенд

- Аналитика преподавателя: фильтры занятие / группа / обучающийся (AND), портфель по состоянию и виду, топ худших и лучших занятий, обучающиеся с порогом 70.
- Убраны блок коррекции преп.−ИИ, KPI «синт. ошибки», вкладка «Статистика» у списка занятий.
- Оценка: кнопки согласия с ИИ и очистки; отступы кнопок в dialog-actions.
- Аналитика обучающегося: динамика за последний месяц, даты на оси X, хронологический порядок.

### Бэкенд

- `AssessmentWeights`: при полном совпадении критериев с ИИ итог берётся из опубликованного `ai.totalScore` (без дрейфа округления).

### Контракт

- без изменений

### Документация

- эта запись history

## Почему так

Итог ИИ считается по «сырым» баллам критериев, а после «Согласен с оценкой ИИ» пересчёт шёл по уже округлённым — получалось расхождение. Порог 70 для обучающихся совпадает с цветовой логикой «ниже 70 — слабо».

## Проверено

- `npm run build` фронтенда, hot-deploy в Docker (`docker cp` + restart), HTTP 200 на localhost:3000
- ручная проверка сценариев в UI по ходу правок

## Не сделано

- выравнивание расчёта итога ИИ в самих оценщиках (по-прежнему сырые баллы; mirrorsAi закрывает кейс согласия)

## Требует внимания

- при согласии с ИИ преподаватель сначала заполняет поля, затем жмёт «Сохранить» — это намеренно отличается от бывшего `confirmAi` на main
