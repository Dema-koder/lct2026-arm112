# 2026-09-30 — лимиты памяти production по фактическому потреблению

**Ветка:** `fix/production-memory-limits`
**Коммит:** `—` (заполнить после коммита)
**Суть:** лимиты контейнеров в `compose.production.yaml` совпадают с серверными; выкладка из CI больше не урежет память бэкенду.

## Что сделано

### Бэкенд

- `compose.production.yaml`: backend 384m → 1g, postgres 192m → 512m, frontend 192m → 512m, proxy 48m → 128m — значения, выставленные на сервере вручную.

### Документация

- `PROJECT_DOCUMENTATION.md` §8, §17: требования к серверу — минимум 2 vCPU / 4 ГБ без модели, 4+ vCPU / 8+ ГБ с моделью.

### Фронтенд, контракт

- без изменений

## Почему так

На сервере бэкенд занимает ~530 МБ (LanguageTool с пулом словарей), при лимите 384 МБ и `ExitOnOutOfMemoryError` он падал бы по кругу. Лимиты под 1 ГБ VPS были подняты на сервере вручную и перезаписались бы первой же выкладкой из CI.

## Проверено

- `docker compose -f compose.production.yaml config`; фактическое потребление на сервере (`docker stats`).

## Требует внимания

- DOCX/PDF документации не пересобраны.
