# 2026-09-19 — три роли, персональные занятия и режим заполнения карточки

**Ветка:** `main`
**Коммит:** [`39c7e89`](https://github.com/Dema-koder/lct2026-arm112/commit/39c7e89)
**Суть:** симулятор АРМ-112 стал учебным сервисом: администратор заводит людей и АРМ, преподаватель раздаёт персональные занятия двух режимов и оценивает поверх ИИ, обучающийся работает то оператором 112, то диспетчером ДДС и видит результаты по правилу вида занятия.

## Что сделано

### Фронтенд

- `page.tsx` разбит: вход общий, дальше по роли — `TraineeShell` / `TeacherShell` / `AdminShell`. Общие куски — в `components/common.tsx` (сокет с переподключением, таймер, тосты, модалка).
- **Экран оператора 112** (`components/fill/`): три телефона, заявитель, 14 полей формализованного адреса + описательный, флаги, «что случилось?» с частыми/значимыми плашками и поиском по части слова, опросная карта, описание со счётчиком `0 / 1999`, оранжевая панель служб с автоподбором и окном «+», единственная кнопка «сохранить», таймер 3 минуты. Поля автосохраняются одним PATCH через 500 мс. Вводная заявителя — жёлтая плашка под телефонами, скрывается кнопкой ☎.
- **Экран ДДС** перенесён в `components/dds/` и дополнен: панель показывает все оповещённые по ЕКП службы, редактируется только своя (`ownServiceCode`), подсказки тренировки жёлтой полосой, следующая карточка приходит после закрытия текущей, «Завершить занятие» — только когда очередь пуста.
- «Мои результаты»: таблица занятий с правилом видимости, разбор оценки, рейтинг и место в группе, материалы группы.
- Преподаватель: список и создание занятия (вид/режим/источник/сценарии/участники галочками), монитор с автообновлением, отчёт с двумя SVG-диаграммами и CSV, разбор сессии с оценкой поверх ИИ, «Опубликовать результаты» для зачёта; библиотека сценариев с редактором эталона; материалы.
- Администратор: пользователи (строка-форма создания, переключатель активности, сброс пароля), группы, настройки с сохранением по blur, журнал аудита с курсором, состояние системы, копии и восстановление с вводом `RESTORE`.
- Стили новых экранов — в `roles.css`, палитра та же; оранжевый используется только на экране оператора 112.

### Бэкенд

- Миграции `V2`–`V5`: `scenario`, `app_user`, `audit_event`, `app_setting`, `training_group`, `lesson`, `training_session`, `assessment`, `material`. Снимок `training_state` теперь на персональную сессию (`state_key = sessionId`).
- RBAC: роль в JWT, `/admin/**` → ADMIN, `/teacher/**` → TEACHER, учебные пути → TRAINEE и TEACHER («делай, как я» — действия преподавателя в ленте с `actorRole = TEACHER`, в оценку не попадают).
- `TrainingEngine` переписан на `Map<sessionId, SessionState>`; сидовые константы удалены; доступ проверяется на каждом вызове (обучающийся — своя сессия, преподаватель — свои занятия, администратор — нет).
- `CardFillService` (черновик из очереди сценариев, PATCH, save → сценарий `TRAINEE_MADE`, автозавершение на последней вводной), `LessonService` (создание, старт с копированием АРМ из учётки, монитор, отчёт, CSV, оценка преподавателя, публикация), `ScenarioService` (сид из 96 билетов, шаблонная генерация), `RatingService`, `BackupService` (JDBC-экспорт в ZIP и восстановление), `SettingsService`, `AuditService` + `AuditFilter` (все не-GET запросы, пароли вырезаются, чистка старше срока, не меньше 180 дней).
- Оценка: `CardFillAssessor` (адрес 40 / тип 20 / службы 20 / время 15 / грамотность 5), `CardActionsAssessor` (время 30 / действия 40 / коммуникация 15 / грамотность 15), `AddressMatcher` (Левенштейн ≤ 2 по улице → критическая опечатка), `LanguageChecker` (смешанные алфавиты, тройные буквы, пунктуация, опечатки в названиях улиц из словаря сценариев).
- `EventService` доставляет события адресно: обучающемуся сессии и преподавателю занятия.
- Сиды: `tools/build_seed.py` собирает `scenarios.json` (96 билетов с уточнённым адресом), `incident-types.json` (35 типов с привязкой к ЕКП), `service-matrix.json` (тип → службы по матрице оповещения), `services.json`; `survey-cards.json` — 14 опросных карт вручную по `card-ui.md`.
- `ApiExceptionHandler` логирует 5xx со стектрейсом, отдаёт 403 на отказ метода-безопасности, 404 на неизвестный путь (долг из history закрыт).

## Почему так

- **Персональная сессия на обучающегося**, а не сессия на класс — решение №1 из ROLES.md: нужны подстройка под человека и рейтинг группы. Снимок состояния на сессию — минимальная правка `TrainingStateStore`, отчёты строятся по таблице `assessment`, поэтому нормализация карточек не понадобилась.
- **Эталон режима заполнения взят из материалов, а не придуман**: курсив в билетах — уточнённый адрес, матрица ЕКП — службы. Опечатка в улице критична, потому что заказчик прямо назвал кейс «Дубнинская / Дубининская» ([q-and-a.md](../docs/materials/q-and-a.md), §6).
- **Оценка преподавателя рядом с ИИ, итог — `coalesce(teacher, ai)`** — решение №5; история оценки ИИ не теряется.
- **Видимость результата по виду занятия** — решение №10; для зачёта API отдаёт `403 RESULTS_NOT_PUBLISHED`, а не пустую оценку.
- **Бэкап через JDBC-экспорт, а не `pg_dump`** — работает в контейнере без клиентских утилит и в тестах на H2; типы восстанавливаются по классу Java-значения, потому что JDBC-типы `uuid`/`timestamptz` у PostgreSQL и H2 расходятся.
- **Аудит фильтром, а не аннотациями** — один `AuditFilter` покрывает «все действия всех ролей» и не даёт забыть новый эндпоинт.
- **Java 19+ и `\b`**: без флага `(?U)` граница слова не видит кириллицу — нормализация адресов молча не работала. Заведено в `TextUtil`.
- **`value` — зарезервированное слово H2**: колонка настроек названа `setting_value`.

## Не сделано

- Адаптивная сложность — намеренно, см. ROLES.md раздел 6: заложены только `scenario.difficulty` и персональные сессии.
- Генерация сценариев моделью: реализована шаблонная (ситуация одного билета + адрес другого); LLM — за флагом, когда будет локальная модель.
- Звук исходящего вызова и стадия `RINGING` с задержкой — задержки теперь настраиваются администратором, но аудиофайлов нет.
- Кэш идемпотентности всё ещё в памяти процесса; transactional outbox между снимком и событиями — нет.
- 20 из 96 билетов не получили тип происшествия автоматически (эвристика по ключевым словам) — преподаватель проставляет в редакторе сценария; эталон для них по типу/службам не считается.
- Материалы для дообучения только хранятся и выдаются; «дообучение» модели не реализовано.

## Требует внимания

- **Контракт `0.3` ломающий**: фронтенд старой версии получит `426`. `additionalProperties: false` по-прежнему требует правки `openapi.yaml` при любом новом поле.
- **`DemoSeeder` срабатывает на пустой базе занятий** и запускает тренировку для `trainee`: в тестах и на стенде первое занятие «уже идёт». Старт нового занятия принудительно закрывает предыдущее активное у того же обучающегося.
- **Восстановление из копии заменяет базу целиком** и перезагружает состояние движка; активные занятия в этот момент прерываются.
- **Служба обучающегося зашита как `101`** (`TrainingEngine.OWN_SERVICE_CODE`); ожидаемое решение «принять / не принять» считается по наличию 101 в матрице ЕКП, если преподаватель не задал явно.
- **Heredoc в Git Bash на Windows** ломался на многофайловых командах — исходники писались через инструмент Write, скрипты — через python.
