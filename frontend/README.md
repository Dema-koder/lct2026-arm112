# Фронтенд обучающегося АРМ-112 ДДС

Интерфейс воспроизводит рабочее место ДДС и работает с REST/WebSocket-контрактом backend из этого репозитория.

## Запуск

Самый короткий способ запустить frontend, backend и PostgreSQL из корня репозитория:

```bash
docker compose up --build
```

После этого откройте `http://localhost:3000`.

Для отдельной разработки frontend потребуются Node.js 22.13+ и npm. Сначала запустите backend и PostgreSQL по инструкции [`docs/POSTGRES_DOCKER.md`](../docs/POSTGRES_DOCKER.md), затем в другом терминале:

```bash
cd frontend
npm install
npm run dev
```

Откройте `http://localhost:3000`.

Тестовая учётная запись:

- логин `trainee`;
- пароль `trainee`.

После входа откройте единственную демонстрационную карточку. Полный успешный сценарий:

1. Нажать плитку `Служба 101` внизу карточки.
2. Выбрать `Принято`.
3. Снова открыть плитку службы и выбрать `Начало реагирования`.
4. Открыть плитку службы, выбрать `Исходящий звонок`, номер `1102`, затем `Вызвать`.
5. Дождаться статуса `Информация принята` и завершить звонок.
6. В меню службы выбрать `Работы завершены` и ввести комментарий.
7. Нажать `Завершить занятие`, чтобы увидеть итоговую оценку.

Учебные данные хранятся в PostgreSQL, поэтому перезапуск backend не сбрасывает карточку. Для полного сброса контейнерного окружения остановите Compose с удалением volume и запустите его заново:

```bash
docker compose down -v
docker compose up --build
```

Команда `down -v` удаляет локальные данные PostgreSQL без возможности восстановления.

## Настройки

Создайте `.env.local`, только если backend работает не на стандартном адресе:

```dotenv
NEXT_PUBLIC_API_BASE_URL=http://localhost:8080/api/v1
NEXT_PUBLIC_WS_URL=ws://localhost:8080/ws/v1
```

## Проверка сборки

```bash
npm run lint
npm test
```

Для отдельной production-сборки:

```bash
npm run build
```

Сценарий интерфейса: вход → очередь карточек → принятие → начало реагирования → исходящий звонок → завершение работ → завершение занятия → оценка.
