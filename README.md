# Учебный тренажёр 112

Учебный сервис подготовки операторов ДДС города Москвы: три роли (администратор, преподаватель, обучающийся), два режима занятий — заполнение карточки оператора 112 и действия с карточкой на АРМ ДДС, персональные занятия, оценка ИИ с приоритетом оценки преподавателя, аудит и резервное копирование. Java/Spring Boot backend, PostgreSQL, web-интерфейс по скриншотам боевого ПОВ-112. Frontend и backend реализуют единый контракт [`docs/contracts/openapi.yaml`](docs/contracts/openapi.yaml) (версия `0.3`).

Роли, права и решения по ним — в [`docs/ROLES.md`](docs/ROLES.md); техническая раскладка по файлам — в [`docs/ROLES_IMPLEMENTATION.md`](docs/ROLES_IMPLEMENTATION.md); пошаговая ручная проверка каждой роли — в [`docs/TESTING_ROLES.md`](docs/TESTING_ROLES.md); план тестирования с чек-листом (безопасность, копии, production) — в [`docs/TEST_PLAN.md`](docs/TEST_PLAN.md).

## Стек

- Java 21;
- Spring Boot 4.1.1;
- Spring Web MVC и Bean Validation;
- Spring Security, JWT HS256;
- access JWT и ротируемый refresh-токен с отзывом;
- raw WebSocket с одноразовым ticket;
- PostgreSQL 17, JDBC и Flyway;
- Maven и Docker Compose;
- React 19, TypeScript и Next.js/vinext;
- REST API и WebSocket для обновления карточки в реальном времени.

## Быстрый запуск через Docker Compose

Понадобится Docker Desktop или Docker Engine с Compose. Java, Maven, Node.js и PostgreSQL устанавливать локально не нужно.

Из корня репозитория выполните:

```bash
docker compose up --build
```

После запуска доступны:

- интерфейс: `http://localhost:3000`;
- backend: `http://localhost:8080`;
- Swagger UI: `http://localhost:8080/swagger-ui.html`;
- PostgreSQL: `localhost:55432`.

Откройте интерфейс: `http://localhost:3000`. Сидовые учётные записи (создаются при первом старте на пустой базе, пароли задаются в `.env`):

| Роль | Логин | Пароль | Что увидит |
|---|---|---|---|
| Обучающийся | `trainee` | `trainee` | АРМ 12, демо-тренировка в режиме заполнения карточки по двум билетам |
| Преподаватель | `teacher` | `teacher` | Занятия (демо-группа), сценарии, материалы |
| Администратор | `admin` | `admin` | Пользователи, группы, настройки, журнал аудита, резервные копии |

Типовой сценарий демонстрации: администратор заводит обучающихся с номерами АРМ и группой → преподаватель создаёт занятие (тренировка / проверка / зачёт, режим, сценарии из билетов, участники галочками) и нажимает «Начать» → у каждого обучающегося появляется своё занятие → преподаватель видит монитор, завершает, ставит оценку поверх ИИ и для зачёта публикует результаты.

Проверка состояния контейнеров и backend:

```bash
docker compose ps
curl http://localhost:8080/actuator/health
```

Остановка без удаления данных:

```bash
docker compose down
```

Состояние занятия сохранится в Docker volume `postgres_data`. Полный сброс демонстрационных данных выполняется отдельной командой, которая безвозвратно удаляет этот volume:

```bash
docker compose down -v
docker compose up --build
```

Подробные варианты запуска, локальная разработка и диагностика описаны в [`docs/POSTGRES_DOCKER.md`](docs/POSTGRES_DOCKER.md).

Интерактивная документация Swagger UI:

```text
http://localhost:8080/swagger-ui.html
```

Swagger использует зафиксированный контракт [`docs/contracts/openapi.yaml`](docs/contracts/openapi.yaml). Перед запросами нажмите **Authorize** и заполните:

- `contractVersion`: `0.3`;
- `bearerAuth`: JWT из ответа `POST /auth/login` без префикса `Bearer` — для защищённых запросов.

Пример входа:

```bash
curl -X POST http://localhost:8080/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -H 'X-Contract-Version: 0.3' \
  -d '{"username":"trainee","password":"trainee"}'
```

Полученный `accessToken` передаётся как `Authorization: Bearer <token>`.

## Реализовано

**Обучающийся**

- экран входа в стилистике АРМ-112 (общий для всех ролей);
- режим **заполнения карточки** (экран оператора 112): вводная «со слов заявителя», три телефона, заявитель, формализованный адрес с описательным, флаги, «что случилось?» с плашками и поиском, опросная карта по типу, описание со счётчиком `0 / 1999`, автоподбор служб по ЕКП на оранжевой панели, единственная кнопка «сохранить», таймер 3 минуты;
- главный экран оператора 112: журнал смены (свои сохранённые и фоновые карточки других АРМ), входящие вызовы со звонком, карточка по принятому вызову, «уточнить адрес у заявителя»; пропущенный вызов — заявитель перезванивает, потерянный — в оценке;
- поток вводных по интенсивности занятия (по одной / низкая / средняя / высокая): карточки и вызовы приходят по таймеру независимо от текущей (см. `docs/ROLES.md`, раздел 1);
- режим **действий с карточкой** (экран ДДС): журнал происшествий, из которого обучающийся сам открывает карточки, полный цикл статусов реагирования, панель всех оповещённых служб с редактированием только своей (служба задаётся в занятии, её плитка всегда есть), исходящий звонок;
- подсказки по ходу в тренировке; результат сразу в проверке; после публикации преподавателем — в зачёте;
- «Мои результаты»: оценки, замечания, рекомендации, рейтинг и место в группе, материалы группы.

**Преподаватель**

- справочники из боевого ПОВ-112: список «что случилось?» (49 позиций) с опросными картами и выводом типа ЕКП из ответов, 216 служб с ДДС районов, округов и поселений (`docs/materials/card-types.md`, `docs/materials/services.md`);
- библиотека сценариев с названиями: 96 билетов, шаблонная генерация, сформированные обучающимися; эталон (адрес, тип, службы, решение ДДС, обязательность доклада) и его подтверждение;
- занятие: вид, режим, источник карточек, сценарии и участники галочками, старт — персональная сессия каждому с его АРМ;
- монитор занятия в реальном времени, принудительное завершение, отчёт (таблица + диаграммы + CSV), оценка поверх ИИ по критериям с комментариями (итог пересчитывается по весам), публикация результатов зачёта;
- методические материалы для групп; видны только свои занятия и группы.

**Администратор**

- учётные записи трёх ролей с номером АРМ и группой, блокировка, сброс пароля; группы и их преподаватели;
- настройки в рантайме: нормативы, телефония, логирование, срок хранения аудита (не меньше 180 дней);
- журнал аудита всех изменяющих запросов всех ролей; хвост лога сервера; состояние сервисов;
- резервные копии БД и файлов материалов: по кнопке и ежедневно, восстановление с подтверждением.

**Ядро**

- персональные сессии, снимок состояния на сессию в PostgreSQL, восстановление после перезапуска;
- независимое поступление карточек во время обработки предыдущих, пакетные одновременные поступления, задержка открытия и параллельные таймлайны служб;
- оценка ИИ: адрес (опечатка в улице — критично), тип, службы, время, грамотность; для ДДС — нормативы, решение по компетенции, полнота комментариев;
- JWT с ролью и немедленным отзывом после блокировки, смены роли или пароля (фронтенд при этом сразу показывает экран входа); масштаб интерфейса A−/A+; RBAC по префиксам, адресная доставка WebSocket-событий, идемпотентность команд, единый формат ошибок, Swagger по контракту.
- PostgreSQL-идемпотентность команд, optimistic locking снимков, транзакционная запись realtime-событий и повторная доставка после сбоя;
- ограничение попыток входа, ротируемые refresh-токены, закрытый Swagger в production;
- Prometheus (`/actuator/prometheus`), health/readiness, метрики входа, WebSocket, очереди, событий и резервных копий;
- атомарные ZIP-копии с SHA-256, сроком хранения и дублированием во внешний каталог; профиль k6 на 20–100 пользователей.

## WebSocket

1. Получить ticket: `POST /api/v1/auth/ws-ticket` с Bearer JWT.
2. Подключиться к `ws://localhost:8080/ws/v1?ticket=<ticket>`.
3. После разрыва запросить пропущенные события через `GET /api/v1/training-sessions/{id}/events?afterSequence=N`.

Ticket одноразовый и действует 30 секунд.

## Проверка

Backend:

```bash
mvn clean verify
```

Интеграционные тесты: полный цикл ДДС с двумя карточками и отчётом преподавателя; заполнение карточки с опечаткой в улице и подсказкой; RBAC, аудит, пользователи, настройки, резервная копия и восстановление; зачёт на двоих с оценкой преподавателя, публикацией и изоляцией преподавателей; unit-тесты сверки адреса и грамотности. Локально без JDK 21 удобно запускать через Docker: `docker run --rm -v "$PWD:/workspace" -w /workspace maven:3.9.9-eclipse-temurin-21 mvn clean verify`.

Frontend:

```bash
cd frontend
npm run lint
npm test
```

Frontend-тест собирает production bundle, проверяет серверный HTML и ключевые точки интеграции с контрактом `0.3` (на Windows: `npx vinext build && node --test tests/rendered-html.test.mjs`).

## Настройки

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `SERVER_PORT` | HTTP-порт | `8080` |
| `SPRING_DATASOURCE_URL` | JDBC URL PostgreSQL | `jdbc:postgresql://localhost:5432/arm112` |
| `SPRING_DATASOURCE_USERNAME` | пользователь PostgreSQL | `arm112` |
| `SPRING_DATASOURCE_PASSWORD` | пароль PostgreSQL | `arm112` |
| `ARM112_JWT_SECRET` | локальный ключ JWT, заменить вне dev | встроенный dev-ключ |
| `ARM112_ALLOWED_ORIGINS` | origins фронтенда через запятую | `http://localhost:3000,http://localhost:5173` |
| `ARM112_SEED_ADMIN_PASSWORD` и др. | пароли сидовых учётных записей | `admin` / `teacher` / `trainee` |
| `ARM112_BACKUP_DIR`, `ARM112_BACKUP_CRON` | каталог и расписание резервных копий | `./backups`, `0 0 2 * * *` |
| `ARM112_BACKUP_EXTERNAL_DIR` | второй каталог копий; в production смонтировать отдельный диск/NFS | выключен |
| `ARM112_BACKUP_RETENTION_DAYS` | срок хранения ZIP-копий и checksum | `14` |
| `ARM112_SWAGGER_PUBLIC` | публичный Swagger; при `false` доступен только администратору | `true` |
| `ARM112_MATERIALS_DIR` | каталог файлов методических материалов | `./materials-store` |
| `ARM112_LOG_FILE` | файл лога (виден администратору в UI) | `./logs/arm112.log` |

Параметры Compose можно переопределить через `.env`; полный пример находится в [`.env.example`](.env.example). В частности, `POSTGRES_PORT`, `BACKEND_PORT` и `FRONTEND_PORT` меняют опубликованные порты хоста.

API-контракт и правила независимой разработки фронтенда и бэкенда находятся в [`docs/contracts/README.md`](docs/contracts/README.md).

Подробная пошаговая инструкция по запуску Swagger, авторизации и прохождению полного учебного сценария: [`docs/frontend/SWAGGER_GUIDE.md`](docs/frontend/SWAGGER_GUIDE.md).

Настройка и команды frontend описаны отдельно в [`frontend/README.md`](frontend/README.md).

Production-выкладка на сервер при каждом push/merge в `main` описана в [`docs/DEPLOYMENT.md`](docs/DEPLOYMENT.md).
